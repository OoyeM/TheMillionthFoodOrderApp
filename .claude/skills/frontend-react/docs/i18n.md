# i18n — Internationalization

## Languages

Belgian market requires three languages from day one:

| Code | Language | Primary Use |
|------|----------|------------|
| `nl` | Dutch (Flemish) | Flanders, Brussels |
| `fr` | French | Wallonia, Brussels |
| `de` | German | East Belgium |

Default: `nl` (configurable per brand/shop).

## Library: react-i18next

```tsx
// src/i18n/config.ts
import i18n from 'i18next';
import { initReactI18next } from 'react-i18next';
import LanguageDetector from 'i18next-browser-languagedetector';

i18n
  .use(LanguageDetector)
  .use(initReactI18next)
  .init({
    fallbackLng: 'nl',
    supportedLngs: ['nl', 'fr', 'de'],
    ns: ['common', 'products', 'orders', 'admin'],
    defaultNS: 'common',
    interpolation: { escapeValue: false }, // React handles XSS
    detection: {
      order: ['path', 'localStorage', 'navigator'],
      lookupFromPathIndex: 1, // /{brand}/{lang}/...
    },
  });
```

## Translation File Structure

```
src/i18n/
  locales/
    nl/
      common.json     ← shared UI (buttons, labels, errors)
      products.json   ← product-related strings
      orders.json     ← order flow strings
      admin.json      ← CMS admin strings
    fr/
      common.json
      ...
    de/
      common.json
      ...
```

## Usage

```tsx
import { useTranslation } from 'react-i18next';

function OrderButton() {
  const { t } = useTranslation('orders');
  return <button>{t('placeOrder')}</button>;
}
```

## Dynamic Content from API

Product names, descriptions, and category names come from the API as `LocalizedString`:

```tsx
// API returns: { nl: "Friet", fr: "Frites", de: "Pommes" }
type LocalizedString = Record<SupportedLocale, string>;

// Helper to resolve current locale
function useLocalizedString(value: LocalizedString): string {
  const { i18n } = useTranslation();
  return value[i18n.language as SupportedLocale] ?? value.nl;
}

// Usage
function ProductName({ name }: { name: LocalizedString }) {
  const localizedName = useLocalizedString(name);
  return <span>{localizedName}</span>;
}
```

## URL Strategy

Language in URL path for SEO and shareability:

```
/frietjes/nl/menu          ← Dutch storefront
/frietjes/fr/menu          ← French storefront
/frietjes/nl/pos/          ← POS (language less important, but consistent)
/frietjes/nl/admin/        ← Admin panel
```

## Currency & Number Formatting

```tsx
// Always format with Belgian locale conventions
const formatter = new Intl.NumberFormat('nl-BE', {
  style: 'currency',
  currency: 'EUR',
});
// → "€ 8,50"

// VAT display
function formatVATRate(eatIn: boolean): string {
  return eatIn ? '21%' : '6%';
}
```

## Translation Workflow

1. Developers add keys in `nl` (primary language)
2. Mark new keys with `// TODO: translate` in `fr` and `de` files
3. Translation happens before feature ships — never ship untranslated keys
4. API-sourced content (product names, etc.) is managed in CMS admin, not in translation files
